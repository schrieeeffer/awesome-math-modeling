# 从赛题到终稿

用于完整建模、论文定稿和提交材料整理。先补齐关键输入，再连续完成必要的计算、写作和检查。用户只改某一问、一段文字或几张图时，执行对应部分即可。

## 1. 读材料，确定当前进度

读取赛题、附件、最新规则、往年参考和已有代码、结果、论文。确认当前使用的文件与用户手动修改；规则、题目事实、建模假设和外部评审意见分别记录。

缺少参赛要求目录、参考论文、输出位置或必要队伍信息时，按 [参考论文适配](reference-adaptation.md) 集中询问。材料齐全后继续推进，已确认的内容直接使用。

用 [项目进度记录](../assets/project-state.md) 保存正式路径、确认过的假设、完成的计算、运行状态和下一步。该记录放在工作目录中，便于中断后恢复。

## 2. 把题意变成可检验的任务

每项要求对应到输入、数学对象、约束、交付物、检验方法和报告位置。明确单位、索引、参数来源与边界条件。预测驱动的调度问题可补读 [动态决策](dynamic-decisions.md)。

先建立一个能够解释问题的基线，再考虑针对具体缺陷的改进。实验前确定评价指标、比较方法和选择规则；学习任务安排数据划分，随机算法记录种子与重复设计。已有证据足够时，把精力放在解释和表达上。

## 3. 先小例验证，再运行完整计算

根据题型安排手算、边界、守恒、可行性或回归检查，尽早发现口径和实现问题。新方案与已有正式结果分开保存，使用相同评价口径比较。

记录运行命令、配置、完成范围、退出状态和结果位置。任务恢复时先核对这些记录及实际产物。可以并行处理相互独立的工作，同时明确文件责任和共享参数，合并时核对版本。

## 4. 写结果，完善论证，再完成摘要

按当前案例提取的结构组织正文，让读者找到方法、答案、比较基准和成立条件。已有成熟稿优先局部修改，保留可靠的结论与有意义的对照。

图表从同一组结果生成，指定表格与附加文件按本届要求放置。先保证最终尺寸下可读，再安排多面板和页面空间。摘要在主要结果确定后完成，突出真正使用的方法、关键答案及必要取舍。

引用、图表与提交细节见 [终稿检查](submission-quality.md)。

## 5. 整理交付文件

按规则明确页数范围、材料位置和命名方式，再整理提交目录。目录中保留当前论文、结果、所需程序和说明；旧版压缩包、过程笔记和临时文件留在工作区。附录目录根据实际交付文件生成。

从同一份源文件生成请求的格式。需要PDF时完成编译或导出，需要Overleaf时另交可移植工程。图型改变后更新图注，附录包含代码时同步更新代码；保留用户已经确认的手动删改。

查看实际页面，核对页数、公式、引用和主要图表。最后交代文件位置、完成的检查和待补信息。填写身份使用用户提供的内容；上传参赛系统按用户明确要求处理。

## 截止前怎么取舍

优先修影响答案和提交的事项，例如计算口径、约束、缺失必填表、页数与匿名问题，再调整语言和视觉。排版修改复用已完成的实验；检查围绕实际改动展开。保留可恢复的版本，减少临近截止时的重复计算和多版本混淆。
