# 论文审查与图表证据检查

用于检查已有论文、章节、代码或图表。先读题目和附件，再核对论文内容，最后查看实际页面中的分页、公式与图表。材料不齐时说明检查范围。来源记录见 [prompt-distillation.md](prompt-distillation.md)。

## 审查顺序与状态

1. 先查会改变答案的错误：漏问、硬约束遗漏、数据口径错误、泄露、公式与实现不一致、无法追溯的关键结果。
2. 再查会削弱结论的缺口：验证不匹配、比较不公平、参数无依据、假设过强、结果解释与证据不相称。
3. 最后查表达与交付：摘要呼应、图表可读、符号与编号、文献对应、最终文件渲染。

用 `已通过`、`存在问题`、`待核验` 或 `不适用` 记录各项状态，并附上判断依据。缺少代码或规则时将相关项留为待核验。已有内容能够支持结论时保留原稿。

| 优先级 | 判断 | 处理 |
|---|---|---|
| P0 | 当前主要答案可能无效，或重要输出缺失 | 先定位并修复模型/数据/计算，冻结依赖结论 |
| P1 | 结论可能成立，但依据或解释不足 | 补合适的检验、来源、比较、适用条件 |
| P2 | 内容成立，表达/图表/排版影响理解 | 保持含义和精度，优化展示并复检 |

P0/P1/P2 是本 skill 的工作优先级，不对应奖项、扣分或官方淘汰规则。依据：W03 P009–P016、P028–P041；W08 P439–P444；W18 P095–P116。

## 题目到答案的一张核对表

逐问建立记录：`题目要求 → 论文位置 → 模型 → 结果/方案 → 验证证据 → 未解决事项`。优先核查：

- 是否保留题目的所有硬约束、特殊定义、单位和所需输出精度；论文是否回答原问题而非更容易的替代问题。
- 各问之间传递的参数、条件与版本是否一致；每个方案是否给出实际决策变量或题目指定附件。
- 假设是否必要、有依据、被使用，且没有通过假设消除题目的关键挑战。
- 全局符号是否统一，局部符号是否就地定义；下标范围、变量域、公式量纲是否自洽。
- 论文的算法步骤、代码实现、参数设置、日志和结果是否相符。

依据：W03 P027–P036；W09 P132–P209、P219–P235、P398–P403。

## 每一个数字和结论都要能回查

维护结果表：`结果ID｜值与单位｜精度口径｜计算/观测/仿真类别｜源文件/位置｜正文/图表/摘要位置`。同一结果的不同显示精度应可由同一原值推出。

- **摘要**：逐问交代关键方法和真正回答题目的结果；重要数字在正文出现，重要方法有实际实现；不为了数字数量补参数或假结果。摘要最后写，篇幅按当年规则与实际版面确定。
- **模型与求解**：解释公式为什么成立、参数从哪里来、如何求解、在哪个条件下停止。现成方法简明引用，将篇幅留给本题转换、改动及验证。
- **结果分析**：按“结果事实 → 可见规律/比较 → 有依据的解释 → 对题目的回答”展开。相关性只能作为相关性，模型假设支持的机制只能写为条件性解释。
- **模型评价**：每个优点指向实际指标或性质；每个局限说明触发条件和后果，再提出对应改进。不把未运行的改进写成已实现贡献。
- **文献**：核验题名、作者、年份、可访问来源，以及是否支持引用处的具体论点；文后条目与文内引用互相对应，不凑文献数。

可用审查句式：

```text
原句：[可定位原文]
问题：[它缺少/混淆了什么]
依据：[题目位置、公式、数据或运行结果]
修改：[保持已证实含义的具体改写，或待完成的计算]
复检：[如何确认问题已消除]
```

依据：W01 P171–P175、P320–P324、P489–P495；W09 P257–P310、P332–P340、P378–P383；W20 P051–P054、P764–P773。审查目的为事实和表达质量，不判断作者是不是 AI。

## 图表先验数据，再验视觉

每张图表应有 `图表ID、要回答的问题、源数据/结果ID、生成脚本、编号图注、正文引用`。缺原数据时不能从低清截图臆造高精度数值；只做可验证的呈现调整，或标明所需数据。示意图不应伪装为实测图，仿真曲线应说明模型和参数。

| 需要展示的内容 | 通常更易读的选择 | 必查项 |
|---|---|---|
| 分类方案数值比较 | 点图、条形图、简洁表格 | 单位、排序逻辑、共同基准；柱长编码数值时通常从零起 |
| 时间变化与预测 | 折线及原始观测点，必要时预测区间 | 时间刻度、训练/预测分界、缺失段、实际值与预测值区分 |
| 两变量关系 | 散点；密集时用透明度、分箱或密度 | 样本量、坐标尺度；拟合线有真实拟合依据 |
| 组间分布 | 箱线/分布图及适量原始点 | n、须线定义、异常点含义；小样本不以平滑密度掩盖信息 |
| 参数扫描与矩阵 | 热力图、曲线、龙卷风图 | 参数范围、基准、色标单位、同系列统一色域 |
| 调度、路径、网络 | 甘特图、路径示意、带语义的网络图 | 时间/方向/容量、节点和边对应真实决策；不能只美观不传达方案 |
| 多指标比较 | 表格、点图或小多图，确有理由时用雷达图 | 量纲与方向已统一，归一化方法明确；雷达面积不作综合优劣证据 |
| 算法和论文关系 | 技术路线或流程图 | 数据流、决策分支、反馈及输出真实；删去无信息节点 |

配色按语义选：类别用可区分的离散颜色；单向数值用有序连续色；围绕有意义基准的正负偏离用发散色。同一对象跨图保持颜色/线型一致，灰度下也尽量可辨。流程图是否黑白、圆角或彩色由论文风格和可读性决定。

只在有统计依据时加入误差棒、置信带、显著性符号，并注明其含义、估计方法与独立样本单位。不能把 SD、SEM、CI 混用，不能给确定性最优值虚构误差棒，也不能根据“差异看起来大”添加 p 值。

补图先判断是否能传递现有正文/表格没有清楚传递的信息；如果表格已经完整回答比较问题，不因字数/图数配额重复画图。仅有定性材料时可画定性结构，不把定性优劣转成虚构分数。

以上依据：W02 P064–P107、P320–P365、P384–P410、P791–P795、P835–P843、P903–P909；W15 P041–P057、P114–P123。图型选择、误差棒条件和数值编码说明是对原文绝对化要求的纠偏。

## 最终文件检查

完整终稿另按 [submission-quality.md](submission-quality.md) 检查正文独立可读、题面小表、附录明确标题、大表选录的授权与说明、AI真实披露和当前文件清单。物理页边界与实际编译产物是计页依据；用户手删文件不得从旧副本恢复。辅助命令为 `python scripts/check_delivery.py --help`，其候选残留不等于确认违规，更不自动删除。

数据图优先保留可编辑/可复现来源及矢量输出，栅格导出按实际插入尺寸选择足够分辨率，常见起点为 300 dpi。真正的验收是嵌入论文后仍能读清字符、坐标、线条和误差，不以 dpi 数字代替目视检查。

- 对最新 Word/PDF 逐页渲染检查，确认无裁切、重叠、乱码、公式缺符号、表格断行和异常空白；图题与图、短表与表题保持合理同页。
- 确认图表/公式编号及交叉引用有效，图注与实际图一致；标题层级清楚，文字精度与数据源一致。
- 如果交付多个格式，核查正文、公式、数字、表格、图注、引用和附录内容一致；不同排版引起页码变化本身不等于内容不一致。
- 按当年赛事官方要求核验页数/摘要/字体/匿名/文件命名/附录/AI 使用说明。外部资料声称的“官方要求”只有核验后才能使用。
- 复运行必要的关键结果，记录命令、输出和限制；不能只检查代码文件存在。

依据：W01 P427–P445、P592–P631；W15 P120–P123；W03 P044–P048。完成后交付已修改文件及仍待核验事项；不输出凭主观评分换算的获奖概率。
