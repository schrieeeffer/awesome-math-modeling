# 摘要起草卡

仅在各问结果和验证已经确定后使用。先从结果台账挑选最能回答题目的记录，再组织语言。

## 写前输入

| 必要信息 | 填写 |
| --- | --- |
| 研究对象与目标 | 〔待填〕 |
| 影响建模的关键条件 | 〔待填〕 |
| 各问采用的模型及其选择依据 | 〔待填〕 |
| 各问关键答案、单位、口径、结果 ID | 〔待填〕 |
| 已执行的验证及结果 ID | 〔待填〕 |
| 结论适用边界 | 〔待填〕 |

## 可变段落骨架

〔对象〕中的〔关键问题〕受到〔核心约束〕影响。本文围绕〔需要完成的任务〕，建立〔总体模型关系，如存在〕。

针对问题〔题号〕，考虑到〔本问难点〕，依据〔输入或处理后的数据〕建立〔模型〕，采用〔求解方法〕得到〔答案和单位〕；〔基线、误差或可行性证据〕表明〔与证据相称的结论〕。

<!-- 根据实际问题数重复上一段；不必每段用完全相同的句法。核心是每问有方法、有结果。 -->

综合〔已验证的结果〕，〔总结最重要发现〕。该结论适用于〔范围〕，在〔尚未验证条件〕下仍需进一步检验。

**关键词：**〔研究对象〕；〔核心模型〕；〔主要方法〕；〔任务〕

## 核验

- 每个数字都能定位到结果台账；单位、分母、样本范围与正文一致。
- 每个问题都能找到答案；摘要不变成算法名清单或任务介绍。
- “降低”“提升”交代相对谁、在什么口径下比较；百分比与百分点不混用。
- “稳定”“鲁棒”“显著”“最优”各有相应证据；没有测试就删除该断言。
- 没有在摘要新增正文缺失的结果、文献或创新点。
- 摘要篇幅按适用规则核对；不为压缩而删去决定解释的条件。
